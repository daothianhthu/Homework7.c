# 과제 07 - 인접 행렬과 인접 리스트의 성능 비교

## 1. 개요

정점이 100개(번호 0 ~ 99)인 **무방향 단순 그래프**를 **인접 행렬(Adjacency Matrix)** 과 **인접 리스트(Adjacency List)** 로 각각 표현하고, 메모리 사용량과 여러 그래프 연산의 비교 횟수를 측정하여 성능을 비교합니다. 자기 자신을 연결하는 간선(Self-loop)과 중복 간선은 만들지 않으며, 간선의 방향은 구분하지 않습니다.

| 그래프               | 정점 수 | 간선 수 | 밀도 (E / 4,950) |
| -------------------- | ------- | ------- | ---------------- |
| 희소 그래프 (Sparse) | 100     | 100     | 약 2.0%          |
| 밀집 그래프 (Dense)  | 100     | 4,000   | 약 80.8%         |

정점 100개인 무방향 단순 그래프의 최대 간선 수는 100 x 99 / 2 = 4,950개입니다.

각 그래프(희소, 밀집)는 한 번만 랜덤 생성한 뒤 **같은 간선 집합**을 인접 행렬과 인접 리스트에 모두 저장합니다. 또한 삽입, 삭제, 연결 확인, 인접 정점 출력에는 두 표현 방식에 **동일한 정점 쌍과 동일한 정점**을 사용합니다. 따라서 표현 방식만 다르고 정점과 간선의 구성은 같습니다.

## 2. 파일 구성

| 파일        | 설명                                        |
| ----------- | ------------------------------------------- |
| `common.h`  | 공통 상수, 구조체, 함수 선언                |
| `main.c`    | main 함수, 실험 순서 제어                   |
| `graph.c`   | 랜덤 간선 생성, 삽입/삭제 대상 정점 쌍 선택 |
| `matrix.c`  | 인접 행렬 구현 및 연산                      |
| `list.c`    | 인접 리스트(연결 리스트) 구현 및 연산       |
| `measure.c` | 측정 결과 출력                              |

## 3. 컴파일 및 실행

```bash
gcc main.c graph.c matrix.c list.c measure.c -o main
./main          # 실행 시각을 시드로 사용 (실행마다 결과가 달라짐)
./main 7        # 시드 7로 고정 (아래 결과를 재현)
```

## 4. 구현 방식

- **인접 행렬:** `int a[100][100]` 을 사용합니다. 간선 (u, v) 가 있으면 `a[u][v] = a[v][u] = 1` 입니다.
- **인접 리스트:** 정점마다 단일 연결 리스트를 두고, 간선 (u, v) 를 삽입하면 u의 리스트에 v를, v의 리스트에 u를 저장합니다 (노드는 리스트의 맨 앞에 삽입).

## 5. 측정 방법

### 5.1 메모리

그래프를 표현하는 자료구조만 계산합니다. 난수 생성용 임시 배열과 프로그램 코드는 제외하며, 그래프를 막 생성한 직후(삽입/삭제 전)에 측정합니다.

- 인접 행렬: `sizeof(int[100][100])` = 100 x 100 x 4 = **40,000 Bytes**
- 인접 리스트: 헤드 포인터 배열 `100 x sizeof(Node*)` = 100 x 8 = 800 Bytes, 그리고 실제 할당된 노드 수 x `sizeof(Node)`. 노드는 `int` + 포인터이며 패딩 때문에 16 Bytes입니다. 노드 수는 리스트를 순회하여 직접 셉니다. `malloc` 의 내부 관리 공간은 포함하지 않습니다.

### 5.2 비교 횟수 기준

행렬의 셀 하나를 확인하거나 리스트 노드 하나를 방문할 때마다 비교 1회로 계산합니다.

| 연산           | 인접 행렬                                | 인접 리스트                                                                           |
| -------------- | ---------------------------------------- | ------------------------------------------------------------------------------------- |
| 간선 삽입      | `a[u][v]` 확인 1회 (없으면 두 위치 갱신) | u의 리스트에서 v가 이미 있는지 확인하며 방문한 노드 수 (없으면 양쪽 리스트 앞에 삽입) |
| 간선 삭제      | `a[u][v]` 확인 1회 (있으면 두 위치 삭제) | u의 리스트에서 v를 찾으며 방문한 노드 수 + v의 리스트에서 u를 찾으며 방문한 노드 수   |
| 연결 여부 확인 | `a[u][v]` 확인 1회                       | u의 리스트에서 v를 찾을 때까지(또는 끝까지) 방문한 노드 수                            |
| 인접 정점 출력 | `a[u][0] ~ a[u][99]` 확인 100회          | u의 리스트에 저장된 노드 수                                                           |

삭제에서 리스트는 두 리스트의 노드를 모두 제거해야 하므로 양쪽 탐색 횟수를 합산하고, 행렬은 한 번의 셀 확인으로 대상 간선의 존재를 확인한 뒤 두 위치를 바로 갱신하므로 1회로 계산했습니다.

### 5.3 실험 입력

- **삽입:** 그래프에 존재하지 않는 서로 다른 정점 쌍 10개를 선택하여 차례로 삽입합니다. 표의 값은 10번 삽입의 **합계**입니다.
- **삭제:** 그래프에 존재하는 서로 다른 간선 10개를 선택하여 차례로 삭제합니다. 표의 값은 10번 삭제의 **합계**입니다.
- **연결 확인:** 임의의 서로 다른 정점 쌍 (u, v) 하나.
- **인접 정점 출력:** 임의의 정점 하나. 인접 정점 목록도 함께 출력하며, 인접 행렬과 인접 리스트의 인접 정점 수가 같은지 프로그램이 검증합니다.

연결 확인과 인접 정점 출력은 그래프를 생성한 직후 상태에서 수행하고, 그 다음 삽입 10회, 삭제 10회를 수행합니다. 모든 정점 쌍은 프로그램이 출력하며 두 표현 방식에서 동일합니다.

## 6. 실험 결과

시드 7로 실행한 결과입니다 (`./main 7`, 전체 출력은 `result_seed7.txt`). 그래프가 랜덤하게 생성되므로 시드에 따라 비교 횟수는 달라질 수 있습니다.

**사용한 입력**

| 그래프 | 연결 확인 쌍 | 인접 정점 출력 정점 | 연결 여부  | 해당 정점의 차수 |
| ------ | ------------ | ------------------- | ---------- | ---------------- |
| 희소   | (18, 13)     | 54                  | 연결 안 됨 | 1                |
| 밀집   | (90, 38)     | 63                  | 연결됨     | 75               |

**측정 결과**

| 측정 항목                       | Case 1<br>희소 - 행렬 | Case 2<br>희소 - 리스트 | Case 3<br>밀집 - 행렬 | Case 4<br>밀집 - 리스트 |
| ------------------------------- | --------------------- | ----------------------- | --------------------- | ----------------------- |
| 메모리 (Bytes)                  | 40,000                | 4,000                   | 40,000                | 128,800                 |
| 간선 삽입 비교 횟수 (10회 합계) | 10                    | 18                      | 10                    | 789                     |
| 간선 삭제 비교 횟수 (10회 합계) | 10                    | 39                      | 10                    | 717                     |
| 연결 여부 확인 비교 횟수        | 1                     | 2                       | 1                     | 41                      |
| 인접 정점 출력 비교 횟수        | 100                   | 1                       | 100                   | 75                      |

**계산 확인**

- 희소 리스트 메모리: 800 + (100 x 2) x 16 = 4,000 Bytes
- 밀집 리스트 메모리: 800 + (4,000 x 2) x 16 = 128,800 Bytes
- 리스트의 인접 정점 비교 횟수는 선택한 정점의 차수와 같습니다 (희소 1, 밀집 75). 평균 차수는 2E/V 이므로 희소 그래프는 2, 밀집 그래프는 80입니다.
- 밀집 리스트의 삽입 평균은 789 / 10 = 약 78.9회, 삭제 평균은 717 / 10 = 약 71.7회입니다. 희소 리스트는 삽입 평균 1.8회, 삭제 평균 3.9회입니다.

## 7. 분석

### 7.1 희소 그래프에서의 차이 (V = 100, E = 100, 밀도 약 2%)

- **메모리:** 인접 리스트는 4,000 Bytes, 인접 행렬은 40,000 Bytes로 리스트가 **10배 적게** 사용했습니다. 행렬은 10,000개의 셀을 저장하지만 값이 1인 셀은 200개뿐이라 공간의 약 98%가 0으로 낭비됩니다. 리스트는 실제 간선 노드 200개와 헤드 배열만 저장합니다.
- **인접 정점 출력:** 선택한 정점의 이웃이 1개뿐이어서 리스트는 1회, 행렬은 100회를 확인했습니다. 행렬은 대부분의 칸이 비어 있어도 한 행 전체를 확인해야 하기 때문입니다.
- **삽입, 삭제, 연결 확인:** 리스트의 길이가 짧아(평균 차수 2) 삽입 18회, 삭제 39회, 연결 확인 2회로 많이 늘지 않았습니다. 행렬은 모두 연산당 1회로 여전히 가장 빠르지만 절대적인 차이는 작습니다.
- **정리:** 희소 그래프에서는 리스트가 메모리와 이웃 탐색에서 크게 유리하고, 간선 조회·삽입·삭제에서의 손해는 거의 없습니다.

### 7.2 밀집 그래프에서의 차이 (V = 100, E = 4,000, 밀도 약 81%)

- **메모리:** 행렬은 40,000 Bytes로 그대로이지만 리스트는 128,800 Bytes로 약 **3.2배** 커졌습니다. 리스트는 노드 8,000개가 각각 16 Bytes를 차지하는 반면, 행렬의 셀은 4 Bytes이고 이미 할당되어 있습니다.
- **연결 확인:** 행렬은 1회, 리스트는 41회였습니다. 리스트는 평균 80개 정도의 이웃을 차례로 확인해야 하므로 찾는 위치에 따라 최대 수십 회가 필요합니다.
- **삽입과 삭제:** 행렬은 각각 10회(연산당 1회)인 반면, 리스트는 삽입 789회, 삭제 717회로 **약 70 ~ 80배** 많았습니다. 삽입은 중복 여부 확인을 위해 u의 리스트 전체(평균 약 80개)를 훑어야 하고, 삭제는 두 정점의 리스트를 모두 탐색해야 하기 때문입니다.
- **인접 정점 출력:** 리스트 75회, 행렬 100회로 차이가 거의 없습니다. 희소 그래프에서 100배 차이였던 리스트의 장점이 사라진 것은 행렬의 한 행에서 대부분의 칸이 실제 간선이기 때문입니다.
- **정리:** 밀집 그래프에서는 행렬이 메모리와 모든 조회·변경 연산에서 유리하고, 리스트의 탐색 장점은 사실상 사라집니다.

### 7.3 밀도가 미친 영향

간선 수가 100개에서 4,000개로 늘어도 행렬의 비용은 변하지 않았습니다 (메모리 40,000 Bytes, 행 스캔 100회, 조회·삽입·삭제 연산당 1회). 반면 리스트의 비용은 평균 차수에 비례하여 증가했습니다 (메모리 4,000에서 128,800 Bytes, 삽입 평균 1.8에서 78.9회, 삭제 평균 3.9에서 71.7회, 인접 정점 1에서 75회). 즉 **행렬의 비용은 정점 수 V에, 리스트의 비용은 간선 수 E와 차수에 의존**합니다.

메모리가 같아지는 지점은 800 + 2E x 16 = 40,000 에서 E 약 1,225개(밀도 약 25%)입니다. 이보다 간선이 적으면 리스트가, 많으면 행렬이 메모리를 덜 사용합니다. 실험한 희소 그래프(E = 100)는 이 기준보다 훨씬 아래에, 밀집 그래프(E = 4,000)는 훨씬 위에 있어 측정 결과와 일치합니다.

### 7.4 어떤 경우에 무엇을 사용하는 것이 적절한가

- **인접 리스트가 적절한 경우:** 희소 그래프, 정점 수가 매우 큰 그래프(예: V = 100,000이면 행렬은 약 40 GB가 필요), BFS·DFS처럼 이웃을 순회하는 알고리즘(전체 비용 O(V + E)), 간선 수의 변화가 큰 그래프.
- **인접 행렬이 적절한 경우:** 밀집 그래프, 정점 수가 작은 그래프, "u와 v 사이에 간선이 있는가?"를 자주 확인하거나 간선을 자주 추가·삭제해야 하는 경우(모두 O(1)), 행렬 연산이 필요한 경우.
- **선택 기준:** 메모리와 이웃 순회가 중요하면 리스트, 상수 시간의 간선 조회·변경과 단순한 구현이 중요하면 행렬을 선택합니다.

## 8. 결론

실험 결과 최적의 표현 방식은 그래프의 밀도와 필요한 연산에 따라 달라집니다. 희소 그래프에서 리스트는 메모리를 10배 절약하고 인접 정점 확인을 100회에서 1회로 줄였지만, 밀집 그래프에서는 메모리를 3.2배 더 사용했고 연결 확인(41회 대 1회), 삽입(789회 대 10회), 삭제(717회 대 10회)가 훨씬 느렸습니다. 행렬은 단일 간선 조회와 변경이 항상 일정하고 빠르지만, 희소 그래프에서는 대부분의 공간을 낭비합니다.
